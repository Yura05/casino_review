# Перенесення сайту на хостинг + домен (з авто-деплоєм)

Гайд саме під **цей** проєкт: FastAPI + Jinja2 + PostgreSQL + готовий статичний
Tailwind CSS. Мета — сайт на власному домені, який **сам оновлюється**, коли ти
запушиш зміни з локального компʼютера (працюючи через Claude Code).

Загальна схема, до якої ми йдемо:

```
правки локально (Claude Code)
   → .\deploy.ps1   (збирає CSS + git commit + git push)
      → GitHub
         → Render підхоплює пуш і САМ переdeployить
            → твій-домен оновлено
```

Рекомендований хостинг — **Render.com**: уміє з коробки FastAPI + керована
PostgreSQL + авто-деплой з GitHub. Для новачка це найменше болю. Альтернатива
(VPS) — у кінці файлу.

---

## Специфіка ЦЬОГО сайту (прочитай перед стартом)

Три речі, без яких деплой зламається:

1. **CSS збирається ЛОКАЛЬНО, не на сервері.** Білдер Tailwind (`tools/`) у
   `.gitignore` — на сервер він не їде. Натомість їде вже зібраний файл
   `app/static/css/tailwind.css` (він НЕ в .gitignore). Тому **перед кожним
   пушем треба зібрати CSS** (`.\build_css.ps1`) і закомітити результат. Скрипт
   `deploy.ps1` (нижче) робить це автоматично.

2. **Налаштування — через змінні оточення, не хардкод.** `app/config.py` читає
   `DATABASE_URL`, `SITE_URL`, `SITE_NAME`, `DEBUG`. Файл `.env` у `.gitignore`
   (секрети не комітимо) — на сервері ці значення задаються в дашборді Render.

3. **`SITE_URL` ОБОВʼЯЗКОВО змінити** з `http://localhost:8000` на
   `https://твій-домен`. Інакше всі абсолютні URL у структурованих даних
   (зірочки-рейтинги, хлібні крихти, лого) вестимуть на localhost і Google їх
   відкине.

> ⚠️ **YMYL-нагадування:** автор оглядів у `seed.py` — заглушка. Перед публічним
> запуском заміни на реальну людину з реальним профілем, інакше Google штрафує
> за вигаданих «експертів» у тематиці азартних ігор. Так само беджі та
> aggregateRating — placeholder.

## Крок 0. Що підготувати

- Акаунт на **GitHub** (приватний репозиторій) — github.com
- Акаунт на **Render** — render.com (реєстрація через GitHub)
- Куплений **домен** (Namecheap / Cloudflare / GoDaddy / тощо)
- Git встановлений локально: перевір `git --version` у PowerShell

---

## Крок 1. Завести git-репозиторій локально

У корені проєкту (`D:\site_revie`) у PowerShell:

```powershell
git init
git add .
git commit -m "Initial commit: casino review site"
```

`.gitignore` уже правильний: не закомітяться `.venv/`, `.env`, `tools/`,
`__pycache__`. А ось зібраний `app/static/css/tailwind.css` — закомітиться (так і
треба).

> Перед комітом переконайся, що CSS свіжий: `.\build_css.ps1` (має вивести
> `Done in ...ms`).

---

## Крок 2. Залити на GitHub

1. На GitHub натисни **New repository** → назва, наприклад `casino-review`,
   обовʼязково **Private** → Create.
2. GitHub покаже команди «…or push an existing repository». Виконай локально:

```powershell
git remote add origin https://github.com/ТВІЙ_ЛОГІН/casino-review.git
git branch -M main
git push -u origin main
```

Тепер код на GitHub. Це і є джерело для авто-деплою.

---

## Крок 3. Створити базу PostgreSQL на Render

1. На render.com → **New +** → **PostgreSQL**.
2. Name: `casino-review-db`. Region: обери найближчий (напр. Frankfurt).
   План: Free (для старту вистачить).
3. Створиться база. На її сторінці знайди **Internal Database URL** — він має
   вигляд `postgresql://user:pass@host/dbname`. Скопіюй.

> ⚠️ **Важливий нюанс цього проєкту:** наш застосунок вимагає драйвер `psycopg2`,
> тому в URL має бути схема `postgresql+psycopg2://`, а Render дає `postgresql://`.
> Коли будеш вставляти URL у змінну `DATABASE_URL` (Крок 4), **заміни початок**
> `postgresql://` → `postgresql+psycopg2://`.

---

## Крок 4. Створити web-сервіс на Render

1. **New +** → **Web Service** → під'єднай свій GitHub-репозиторій `casino-review`.
2. Налаштування:
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - **Health Check Path:** `/health`  (у нас уже є цей ендпоінт)
   - **Auto-Deploy:** Yes (це і є магія — пуш у `main` = авто-деплой)
3. Розділ **Environment** → додай змінні:

   | Key | Value |
   |-----|-------|
   | `DATABASE_URL` | *(Internal URL з Кроку 3, зі схемою `postgresql+psycopg2://`)* |
   | `SITE_URL` | `https://твій-домен` (поки можна тимчасовий `.onrender.com`) |
   | `SITE_NAME` | назва сайту (як показувати) |
   | `DEBUG` | `false` |

4. **Create Web Service** → Render збере і запустить застосунок.

---

## Крок 5. Створити таблиці та наповнити даними (один раз)

Після першого успішного деплою таблиць у базі ще немає. На сторінці web-сервісу
відкрий вкладку **Shell** і виконай по черзі:

```bash
python -m app.init_db    # створює всі таблиці (create_all)
python -m app.seed       # наповнює демо-даними (казино, бонуси, блог, автор)
```

> Міграції `app/migrate_*` тут **не потрібні**: вони для оновлення вже існуючої
> бази. На чистій базі `init_db` одразу створює всі колонки (включно з `badges`,
> `wager`, `min_deposit`), бо вони вже є в моделях.

Перевір: відкрий URL сервісу (`https://...onrender.com`) — має відкритися сайт.

---

## Крок 6. Підключити власний домен

1. На сторінці web-сервісу → **Settings** → **Custom Domains** → **Add** →
   введи свій домен (і `www.`, якщо треба). Render покаже, які DNS-записи додати.
2. Зайди в панель свого реєстратора домену (де купував) → DNS-налаштування:
   - для кореневого домену — `A` або `ALIAS/ANAME` запис на адресу від Render;
   - для `www` — `CNAME` на `...onrender.com` (Render підкаже точні значення).
3. Зачекай поки DNS пошириться (від кількох хвилин до кількох годин). Render
   автоматично видасть безкоштовний **HTTPS-сертифікат** (Let's Encrypt).
4. Коли домен заробив — повернись у **Environment** і онови `SITE_URL` на
   фінальний `https://твій-домен`, збережи (Render передеплоїть).

✅ Сайт у проді на твоєму домені.

---

## Крок 7. Авто-деплой при подальших правках (головне твоє питання)

Тепер цикл оновлення максимально простий. Після будь-яких змін локально
(через Claude Code) у PowerShell з кореня проєкту:

```powershell
.\deploy.ps1 "короткий опис що змінив"
```

Цей скрипт (лежить у корені проєкту):
1. збирає свіжий Tailwind CSS;
2. робить `git add` + `git commit` з твоїм описом;
3. `git push` у GitHub.

Render бачить пуш → автоматично перезбирає й оновлює сайт за 1–3 хвилини.
**Більше нічого робити не треба.** За статусом деплою стеж у дашборді Render
(вкладка **Events / Logs**).

> Якщо змінював **структуру БД** (нові колонки/таблиці в моделях) — це окремий
> випадок: `git push` оновить КОД, але не змінить уже існуючі таблиці. Тоді треба
> або написати міграцію (як `app/migrate_*`) і запустити її через Render Shell,
> або (на демо-етапі, коли дані не шкода) перестворити: у Shell
> `python -m app.init_db`. Скажи Claude — допоможе з міграцією.

---

## Типові помилки та як полагодити

| Симптом | Причина / фікс |
|---------|----------------|
| Деплой падає на `psycopg2` / не конектиться БД | У `DATABASE_URL` забув схему `postgresql+psycopg2://` |
| Сайт відкривається, але без стилів | Не закомітив свіжий `app/static/css/tailwind.css`. Запусти `.\build_css.ps1`, потім `deploy.ps1` |
| У структурованих даних URL на localhost | `SITE_URL` досі `http://localhost...`. Онови env-змінну на проді |
| `Internal Server Error` після першого деплою | Не виконав Крок 5 (`init_db` + `seed`) — таблиць немає |
| Зміни не зʼявляються на домені | Перевір вкладку Events на Render: деплой міг впасти; або Auto-Deploy вимкнено |

## Альтернатива: власний VPS (більше контролю, дешевше на масштабі)

Якщо захочеш повний контроль (Hetzner ~4–5 €/міс):

1. Орендувати VPS (Ubuntu), зайти по SSH.
2. Поставити Python, PostgreSQL, nginx, git.
3. `git clone` репозиторію, `python -m venv`, `pip install -r requirements.txt`.
4. Створити `.env` з реальними значеннями; `python -m app.init_db && python -m app.seed`.
5. Запустити uvicorn під **systemd** (автозапуск/рестарт), за **nginx**
   (reverse proxy + HTTPS через certbot/Let's Encrypt).
6. DNS домену → IP сервера.
7. Авто-деплой: налаштувати **GitHub Actions** (по пушу — SSH на сервер,
   `git pull` + рестарт сервісу) або вебхук.

VPS гнучкіший, але кроків більше й усе адмініструєш сам. Для старту Render
простіший; перейти на VPS можна будь-коли (код той самий).
